# Blog API specification review — 2026-08-25

## Result

The initial Blog API specification set is internally consistent and was approved
by the owner on 2026-08-25 in dependency order. OpenAPI contract work may begin;
production implementation remains gated on completing the contract and mapped
failing tests required by the repository workflow.

## Approved order and decisions

### 1. Platform foundation

Approval accepts:

- ASP.NET Core on .NET 10 and PostgreSQL objects owned in the `blog` schema.
- A Blog-specific `X-Admin-Key`, database principal, migration history, and
  secret configuration independent from the Presentation API.
- UUIDv7 IDs, UTC timestamps, soft deletion, ETags, JSON Merge Patch, Problem
  Details, administrative header pagination, health checks, and OpenAPI 3.1.
- Explicit environment-specific CORS origins and encrypted production secret
  injection with no wildcard or checked-in fallback.

### 2. Article media

Approval accepts:

- Cloudinary Free as the initial storage and CDN provider behind a
  provider-neutral media adapter and public article schema.
- Signed server-side uploads only; Cloudinary credentials never reach the
  frontend.
- JPEG, PNG, and WebP input up to 10 MiB and 25 megapixels; animated and active
  formats are rejected.
- Metadata stripping and one normalized immutable asset bounded to 1600 pixels,
  with responsive variants deferred until measurement justifies them.
- Versioned Cloudinary delivery URLs, relational current-and-revision reference
  tracking, and no physical deletion while any reference remains.
- The privacy limitation that standard delivery URLs are public to anyone who
  learns them; this pipeline is not for confidential images.

### 3. Article publishing

Approval accepts:

- `Writing`, `Draft`, `Published`, `NotListed`, and `Archived` lifecycle states;
  only Published is anonymous, and restore always returns an article to Draft.
- Immutable slug and first-publication timestamp after first publication.
- Versioned structured blocks rather than Markdown or arbitrary HTML.
- A cursor-paginated public summary feed and stable public detail route with
  conditional caching and indistinguishable private-state `404` responses.
- Deterministic reading time at 200 prose words per minute plus 12 non-blank code
  lines per minute, rounded up to at least one minute.
- Immutable full revisions for every state-changing mutation, SEO fallbacks,
  derived canonical URLs, tags, and provider-neutral media projections.
- Explicit version 1 compatibility: incompatible fields, cursor changes, or
  blocks require coordinated body or HTTP versioning.

### 4. Article series

Approval accepts:

- Many-to-many membership with no manual part numbers; public members order by
  article creation time and UUID.
- Article lifecycle changes filter public series reads without mutating
  membership or series revision history.
- Series lifecycle meanings shared with articles, immutable slug and
  first-publication timestamp after publication, and Draft-on-restore behavior.
- Reuse of the complete public article-feed summary schema for series members.

## Cross-repository follow-up after approval

The approved Blog OpenAPI contract will require the frontend to:

- replace its handwritten Blog transport types with a generated client;
- consume `bodyVersion: 1` and the approved block discriminator schemas;
- retain opaque `nextCursor` values without parsing them;
- treat image URLs as opaque while using API-provided alt text and intrinsic
  dimensions;
- enable `/articles` and `/articles/:slug` only after contract and integration
  tests pass.

## Verification performed

- Every feature spec contains the required outcome, scope, workflow, HTTP, data,
  security, acceptance, evidence, and decision sections.
- Authoring format, visibility, slug stability, revisions, scheduling,
  sanitization, media, SEO, search, caching, and backward compatibility are
  either specified or explicitly out of scope.
- Remaining design questions were resolved; deployment values such as the
  actual public origin remain runtime configuration rather than product-contract
  ambiguity.
- No production source, dependency, migration, or OpenAPI file has been added
  before approval.
